# Controlled visual studies

Use this bridge for image-generated slide studies. It assembles the existing density, typography, composition and aesthetic guidance into every tool request. The host calls its available image-generation tool using the exact prepared request, saves the returned bitmap, and records it. The script verifies recorded inputs and decisions. An independent agent still has to inspect the actual images and judge visual quality.

Prepare one study per page using `node <skill-root>/scripts/visual-study.mjs prepare <plan.json> <new-run-dir>`. The plan contains `author`, `brief` (audience and question), `pageId`, `content` (facts, qualifiers and source locations), optional `taste`, `references` and `variants`. Each reference has `path`, `description` and a `role` of `source`, `design`, `approved` or `rejected`. Each variant has an `id` and a `prompt` describing the content-specific composition. Resolve paths relative to the plan. Personal examples and preferences live in the user's local project or configuration.

The author chooses candidate compositions before generating them. On a visual-direction trial, compare a small number of genuinely different ways to organize the same evidence. Keep the factual question constant. Choose how much space the figure needs from its explanatory work. Keep baselines, differences, causes, conditions and consequences together where they help answer the question. Compact type, ordinary bullets, aligned rows and local annotations can increase readable detail. The source boundary and viewing conditions determine how much belongs on the page.

Inspect the listed reference images and call the image tool with `prompt`, `referenced_image_paths` and `transparent_background` from `requests.json` verbatim. Save the original tool image and run `node <skill-root>/scripts/visual-study.mjs record <run-dir> <candidate-id> <png>`. This produces a receipt with the image and prompt hashes. Tool invocation logs remain the evidence that the host used the request.

Give a separate reviewer the effective guidance, factual sources, approved/rejected examples and actual candidate images, without the author's defense of the design. The reviewer compares at equal display width and judges each candidate on four axes. Density covers source-backed comparisons, explanations and useful qualifiers visible together. Hierarchy covers title, body, labels, grouping and type weight. Relationships covers figure-to-text correspondence and reading order. Fidelity covers numbers, units, conditions and truthful imagery. Each axis needs a pass/fail decision and a concrete visible observation. Attractive fill and large lettering do not demonstrate density.

The review JSON contains `reviewer`, `pageId`, `selected` (a candidate id or `null`) and `candidates`. Every generated candidate needs its `id`, `imageSha256` from the receipt and the four objects `density`, `hierarchy`, `relationships`, `fidelity`, each with `pass` and `observation`.

Run `node <skill-root>/scripts/visual-study.mjs check <run-dir> <review.json>`. A failed visual axis prevents acceptance. Give the author's next round the concrete findings, preserve the earlier candidates, prepare a new run and review the returned images again. Carry accepted pages forward without regenerating them. Show unresolved findings honestly if the agreed budget is exhausted. The check validates independent recorded acceptance of the exact bitmap; it cannot measure taste or force an arbitrary host to use this bridge.
