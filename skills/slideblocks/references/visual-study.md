# Controlled visual studies

Use this bridge for image-generated slide studies. It assembles shared visual-evidence, density, typography, composition and aesthetic guidance into the actual generation request, independent review brief and checked implementation handoff. The host must pass those prepared contents to the relevant tool or agent, together with the listed images. The script verifies recorded inputs and decisions; an independent agent still has to inspect actual pixels and judge quality.

Prepare one study per page using `node <skill-root>/scripts/visual-study.mjs prepare <plan.json> <new-run-dir>`. The plan contains `author`, `brief` (audience and question), `pageId`, `content` (facts, qualifiers and source locations), optional `taste`, `references` and `variants`. Each reference has `path`, `description` and a `role` of `source`, `design`, `approved` or `rejected`. Each variant has an `id` and a `prompt` describing the content-specific composition. Resolve paths relative to the plan. Personal examples and preferences live in the user's local project or configuration.

Full-slide studies approve **composition only**, never factual imagery or quantitative geometry. Preserve originals and frozen source data outside the generated bitmap. If exact evidence cannot survive generation, add optional `placeholders`, each with `description` and `replaceWith` naming one of the plan's original `source` reference paths. The study must visibly label these regions as placeholders; the implementation must replace them with originals or verified source-data drawings. Unlabeled repaints and unsupported captions still fail fidelity. This is not permission to pass a false chart as evidence.

The author chooses candidate compositions before generating them. On a visual-direction trial, compare a small number of genuinely different ways to organize the same evidence. Keep the factual question constant. Choose how much space the figure needs from its explanatory work. Keep baselines, differences, causes, conditions and consequences together where they help answer the question. Compact type, ordinary bullets, aligned rows and local annotations can increase readable detail. The source boundary and viewing conditions determine how much belongs on the page.

Inspect the listed reference images and call the image tool with `prompt`, `referenced_image_paths` and `transparent_background` from `requests.json` verbatim. Save the original tool image and run `node <skill-root>/scripts/visual-study.mjs record <run-dir> <candidate-id> <png>`. This produces a receipt with the image and prompt hashes. Tool invocation logs remain the evidence that the host used the request.

Give a separate reviewer the complete prepared `reviewer-brief.md` and actual candidate/source/design images, without the author's defense of the design or candidate prompts. The brief includes the effective guidance, audience question, facts, reference roles, placeholder boundary, image paths and four-axis judgments. It compares source-backed objects, comparisons, states and qualifications; heading/body hierarchy; figure-to-text correspondence; and factual fidelity at equal display width. Attractive fill and large lettering do not demonstrate density. Review composition placeholders only for their placement and truthful labeling.

The review JSON contains `reviewer`, `pageId`, `selected` (a candidate id or `null`) and `candidates`. Every generated candidate needs its `id`, `imageSha256` from the receipt and the four objects `density`, `hierarchy`, `relationships`, `fidelity`, each with `pass` and `observation`.

Run `node <skill-root>/scripts/visual-study.mjs check <run-dir> <review.json>`. A failed visual axis prevents acceptance. Give the author's next round the concrete findings, preserve the earlier candidates, prepare a new run and review the returned images again. Carry accepted pages forward without regenerating them. Show unresolved findings honestly if the agreed budget is exhausted. The check validates independent recorded acceptance of the exact bitmap; it cannot measure taste or force an arbitrary host to use this bridge.

The lead still inspects the selected result against the professional reference and audience question. If it finds a material failure after a reviewer pass, run `node <skill-root>/scripts/visual-study.mjs hold <run-dir> <finding.json>`. The finding contains candidate `id`, `imageSha256`, `reporter` and a concrete `observation`. This blocks both `check` and `handoff` for that bitmap. Preserve the held round; repair the finding in a new study, revisiting sources and the existing page plan when the missing information requires it. Do not clear a hold by editing an old receipt or merely rewriting the review.

After selection, run `node <skill-root>/scripts/visual-study.mjs handoff <run-dir> <review.json>`. Save the returned JSON with the working study records and pass its complete `prompt` to the implementer, plus `selectedImage` and the images in `referenceImages`. The command rechecks the exact bitmap, inputs, independent decision and any held finding. The handoff injects the same visual guidance and factual brief, original-replacement instructions and native comparison checks. It returns `approvalScope: "composition-only"` and `evidenceApproved: false`; the native page must independently pass source, layout, live, reduced-motion and offline/export review. Record native findings and repairs in the existing QA report.

The generated briefs and JSON receipts are execution handoffs, not additional planning authorities. Keep `.slideblocks/page-plan.md` as the design authority. A host with no delegation can use the same injected guidance for explicit self-review, but cannot claim an independent pass; use the documented reference-led fallback rather than inventing a reviewer identity.
